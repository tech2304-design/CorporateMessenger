# Руководство по развертыванию на реальных устройствах

## Проблема

Приложение работает на эмуляторе, но падает после авторизации на реальном устройстве.

## Причина

IP-адрес `10.0.2.2` - это специальный адрес Android эмулятора для доступа к localhost хост-машины. На реальных устройствах этот адрес не работает.

## Решение

Все настройки сервера теперь централизованы в файле `ServerConfig.kt`.

### Шаг 1: Определите IP адрес сервера

#### Для локального тестирования (сервер на вашем компьютере)

**Linux/Mac:**
```bash
ifconfig | grep "inet "
# или
ip addr show
```

**Windows:**
```cmd
ipconfig
```

Найдите ваш локальный IP адрес (обычно начинается с `192.168.x.x` или `10.0.x.x`).

**Важно:** Убедитесь, что устройство и компьютер находятся в одной Wi-Fi сети!

#### Для продакшена

Используйте публичный IP адрес или доменное имя вашего сервера (например, `messenger.example.com` или `203.0.113.10`).

### Шаг 2: Обновите конфигурацию

Откройте файл `app/src/main/java/com/example/messenger/network/ServerConfig.kt` и измените:

```kotlin
object ServerConfig {
    const val SERVER_HOST = "192.168.1.100"  // Ваш IP адрес
    const val SERVER_PORT = 12345
}
```

### Шаг 3: Пересоберите приложение

1. В Android Studio: **Build → Clean Project**
2. Затем: **Build → Rebuild Project**
3. Установите приложение на устройство: **Run → Run 'app'**

## Примеры конфигурации

### Для эмулятора
```kotlin
const val SERVER_HOST = "10.0.2.2"
```

### Для реального устройства (локальная сеть)
```kotlin
const val SERVER_HOST = "192.168.1.100"  // IP вашего компьютера
```

### Для продакшена
```kotlin
const val SERVER_HOST = "messenger.example.com"
// или
const val SERVER_HOST = "203.0.113.10"
```

## Проверка подключения

### 1. Проверьте доступность сервера

С устройства попробуйте открыть в браузере:
```
https://[SERVER_IP]:12345
```

Вы должны увидеть ошибку SSL (это нормально), но не ошибку "Сайт недоступен".

### 2. Проверьте настройки безопасности сети

Android требует использования HTTPS для внешних соединений. Убедитесь, что:
- Сервер использует SSL/TLS (это уже настроено в `main.py`)
- В `network_security_config.xml` разрешены пользовательские сертификаты (для debug)

### 3. Проверьте файрвол

Убедитесь, что порт 12345 открыт на сервере:

**Linux:**
```bash
sudo ufw allow 12345
# или
sudo iptables -A INPUT -p tcp --dport 12345 -j ACCEPT
```

**Windows:**
```
Windows Firewall → Advanced Settings → Inbound Rules → New Rule
→ Port → TCP → 12345 → Allow the connection
```

## Устранение неполадок

### Приложение падает сразу после авторизации

**Причина:** Не может подключиться к серверу для загрузки списка контактов.

**Решение:**
1. Проверьте, что `SERVER_HOST` указывает на правильный IP
2. Убедитесь, что сервер запущен
3. Проверьте, что устройство и сервер в одной сети
4. Проверьте логи сервера: `tail -f server/logs/messenger_*.log`

### Ошибка "Connection refused"

**Решение:**
1. Убедитесь, что сервер запущен: `python3 server/main.py -d`
2. Проверьте, что сервер слушает на `0.0.0.0`, а не на `127.0.0.1`
3. Проверьте файрвол

### Ошибка "Network unreachable"

**Решение:**
1. Устройство и сервер должны быть в одной сети
2. Проверьте IP адрес сервера
3. Попробуйте пинговать сервер с устройства (используйте приложение типа PingTools)

### SSL/TLS ошибки

**Решение:**
1. Для debug-сборки: пользовательские сертификаты разрешены в `network_security_config.xml`
2. Для release-сборки: используйте сертификаты от доверенного CA

## Release сборка

Для production release:

1. Обновите `SERVER_HOST` на продакшн адрес
2. Используйте сертификат от доверенного CA
3. Включите minification в `build.gradle`:
```gradle
buildTypes {
    release {
        minifyEnabled true
        proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
}
```

4. Создайте подписанный APK:
   - **Build → Generate Signed Bundle / APK**
   - Выберите **APK**
   - Создайте или используйте существующий keystore

## Дополнительная информация

### Логирование

Включите debug логи на сервере для диагностики:
```bash
python3 server/main.py -d
```

### Мониторинг подключений

В логах сервера вы увидите:
- `Connection from (IP, PORT)` - новое подключение
- `User username (ID: N) authenticated` - успешная авторизация
- `User N disconnected` - отключение пользователя

### Порты

По умолчанию используется порт `12345`. Чтобы изменить:
1. В `server/main.py` измените `PORT = 12345`
2. В `ServerConfig.kt` измените `SERVER_PORT = 12345`
